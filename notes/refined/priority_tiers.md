# Priority Tiers

Priority tiers will help us prioritize the work that will be most helpful to me immediately. Priority tiers can be referred to as phases.

## P0

Things in P0 are needed to cover the most common use cases. Basically when P0 items are complete, we should support 90% of moves. During this priority, we will constrain ourselves to focusing on handling one specific metronome user species and only one user, with a known moveset.

## P1

Handling obscure edge cases that we can account for in a run without too many additional use cases.
* Switching out Pokemon (only in specific circumstances, like Transform or U-Turn)
* Might add support for a single metronome user fainting

## P2

Trying out best to handle ALL possible use cases, including having a team of possibly 6 metronome users, all with Lagging Tails. Doing our best to guarantee a solution, no matter the resource cost.
* Focusing on supporting only the most immediately useful metronome users. 
* Switching out as a branching path instead of a predetermined action.

## P3

Supporting use cases where another user might not have the same resources as I do: Different metronome users, different held items, etc.
