# GEMINI.md

This file provides project-specific guidance and conventions for the Gemini CLI agent.

## Project Overview
Clayton is a Pokemon HGSS Safari Zone RNG manipulation toolkit. It calculates optimal datetimes to load a save, identifies seeds from game observations, and solves capture paths (using BFS/DFS) to maximize success rates for rare Safari Zone pokemon (primarily Metang).

## Workflow & Task Management

### Issue Tracking (`bd`)
This project uses **beads (bd)** for ALL task tracking. Do NOT use markdown files (like `todo.md`) or other task runners for tracking work.
- **Find Work**: `bd ready` (unblocked) or `bd list --status=open`.
- **Create Task**: `bd create --title="..." --description="..." --type=task|bug|feature --priority=2`.
- **Claim Work**: `bd update <id> --claim`.
- **Close Work**: `bd close <id>`. **CRITICAL**: Always close completed issues before ending a session.
- **Context**: Run `bd prime` for full workflow details.

### Persistent Memory
- **Knowledge Base**: Use `bd remember "insight"` for persistent knowledge across sessions.
- **Search**: `bd memories <keyword>`.
- **Prohibited**: Do NOT use `MEMORY.md` files; they fragment context. Use beads memories instead.

## Core Components

### Chart (`claytonlib/chart/`)
Evaluates potential seeds across candidate datetimes to find optimal target times.
- **Evaluation**: `evaluation.py` performs sliding-window aggregation of success probabilities.
- **Strategies**: `Strategy` wraps action-selection logic; `SuccessCriteria` defines what counts as a win.
- **Chains**: `chain.py` simulates the full "chain" of RNG states for a given seed to evaluate its quality.

### Compass (`claytonlib/compass.py` & `compass_metronome.py`)
Interactive tools for identifying which seed was actually hit by observing game events.
- **Safari Compass**: Narrows down candidate seeds based on turn-by-turn outcomes: mud/bait effects, ball shakes, and flee events.
- **Metronome Compass**: Identifies seeds by observing the moves generated by Metronome in battle. Uses `claytonlib/basedata/moves.json` for move-to-index mapping.
- **Input Syntax**: Fast, single-character inputs (e.g., `m`, `b`, `0-3`, `F`, `C`) for rapid narrowing.

### Machete (`claytonlib/machete.py`)
Pathfinding algorithms to find the sequence of actions that maximize capture probability.
- **Solvers**:
  - `machete_one`: BFS to find the shortest capture path for a single known seed.
  - `machete_all`: Exhaustive DFS to find all possible capture paths within a turn limit.
  - `machete_jane`: Builds an optimal decision tree (`JaneNode`) using recursive probability analysis.
- **Optimization**: Uses `safari_compact.py` (bit-packed state) for high-performance simulation during searches.
- **Parallelism**: Supports `ProcessPoolExecutor` for complex `machete_jane` computations.

## Key Logic & Terminology
- **Timing**: Use **59.8261 Hz** for delay calculations (1 delay = 1 vblank).
- **RNG**: Standard LCRNG: `(state * 1103515245 + 24691) & 0xFFFFFFFF`.
- **Seeds**: There are two seeds per delay (due to the second-tick state).
- **Compass Inputs**: 
  - `m`/`M`: Mud / Mud-crit
  - `b`/`B`: Bait / Bait-crit
  - `0-3`: Ball shakes
  - `F`: Fled
  - `C`: Captured
- **Flee Logic**: `filter_fled=True` indicates the pokemon **stayed** (did not flee).
